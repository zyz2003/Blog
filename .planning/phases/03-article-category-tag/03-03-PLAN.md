    Add public-facing query methods to ArticleRepository. All must filter status='PUBLISHED' AND isTakedown=false AND deletedAt IS NULL.

    **listPublic(options: { page, pageSize, categoryName?, tagName?, year?, month? })**:
    - Build conditions array: eq(articles.status, 'PUBLISHED'), eq(articles.isTakedown, false), isNull(articles.deletedAt)
    - If categoryName provided: join article_post_categories -> post_categories where postCategories.name = categoryName
    - If tagName provided: join article_post_tags -> post_tags where postTags.name = tagName
    - If year provided: add condition on year from articles.createdAt
    - If month provided: add condition on month from articles.createdAt
    - Paginate: limit = pageSize, offset = (page - 1) * pageSize
    - Order by: pinSort ASC, createdAt DESC (matches Go sort)
    - Also run count query for total
    - Return articles with joined categories and tags

    **listHome()**:
    - Select where status=PUBLISHED, isTakeup=false, showOnHome=true, deletedAt IS NULL
    - Order by pinSort ASC, homeSort ASC, createdAt DESC
    - Return with joined categories and tags
    - Per D-51, no pagination — returns all home-visible articles

    **getRandom()**:
    - Select 1 random published non-takedown non-deleted article
    - SQLite: ORDER BY RANDOM() LIMIT 1
    - Return with relations

    **listArchives()**:
    - Select createdAt from all published non-takedown non-deleted articles
    - Group by year and month extracted from createdAt
    - Return array of { year, month, count }
    - In service layer, this gets transformed to Go's ArchiveSummaryResponse format

    **getArticleStatistics()**:
    - Aggregate queries: total posts count, total words sum, average words, total views sum
    - Per-category article counts: join articles with article_post_categories and post_categories, group by category name
    - Per-tag article counts: join articles with article_post_tags and post_tags, group by tag name
    - Top 5 viewed articles: select id, title, view_count, cover_url where published, order by view_count DESC LIMIT 5
    - Publish trend: group by month (format "YYYY-MM"), count per month, last 12 months
    - Return raw data; service layer formats into ArticleStatistics response

    **findByAbbrlinkOrId(slugOrId: string)**:
    - First try: select where abbrlink = slugOrId AND status=PUBLISHED AND isTakedown=false AND deletedAt IS NULL
    - If not found, try decodePublicID(slugOrId), validate entityType=Article, then select by dbId
    - Return with relations (categories, tags)

    **findPrevNextArticles(dbId, createdAt, categoryDbIds?)**:
    - Prev article (newer): select where status=PUBLISHED AND isTakedown=false AND deletedAt IS NULL AND createdAt > currentCreatedAt, order by createdAt ASC LIMIT 1
    - Next article (older): select where status=PUBLISHED AND isTakedown=false AND deletedAt IS NULL AND createdAt < currentCreatedAt, order by createdAt DESC LIMIT 1
    - Per Pitfall 4 in RESEARCH.md: Go swaps prev/next semantically. "prev" = chronologically next (newer), "next" = chronologically prev (older). The repository returns raw chronological neighbors; the service handles the swap

    **incrementViewCount(dbId)**:
    - UPDATE articles SET view_count = view_count + 1 WHERE id = dbId
    - Per D-65, simple DB increment for Phase 03
