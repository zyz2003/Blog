  <action>
Wire the thinnest path through every backend hardening layer in one pass:

1. **chat.schema.ts — add userId field (per D-391):** Add `userId: integer('user_id')` to chatConversations table (nullable — anonymous=null, logged-in=DB ID). This is a one-way migration (adding column is easy, removing requires new migration).

2. **chat-history.service.ts — extend with 3 new methods:**
   - `listConversationsPaged(page: number, pageSize: number): Promise<{ list: StoredConversation[], total: number }>` — paginated query on chatConversations ordered by updatedAt DESC. Count total rows for pagination. Include message count via subquery or separate count.
   - `getConversationMessages(publicId: string): Promise<StoredMessage[]>` — reuse existing getMessages() logic, this is an alias that the controller calls. The existing getMessages already does decodePublicID + query.
   - `deleteConversation(publicId: string): Promise<void>` — decode publicId to dbID, delete all chatMessages with that conversationId, then delete the chatConversations row. Order: messages first (FK), then conversation.
   - Update `createConversation` to accept optional `userId: number | null` parameter and store it.

3. **chat.service.ts — 4 hardening changes:**
   - **System prompt from settings (per D-392):** Replace hardcoded SYSTEM_PROMPT with `this.settings.get('ai_chat_system_prompt') || DEFAULT_SYSTEM_PROMPT` where DEFAULT_SYSTEM_PROMPT is the current Chinese string. Read this inside chat() method (not constructor) so runtime config changes take effect.
   - **prepareStep compression (per D-380, D-381):** Add `prepareStep` callback to streamText options. When `messages.length > 20`, keep the system message (first if role=system) + generate a summary of old messages using `generateText` (import from 'ai') + keep the most recent 10 messages. The summary message has role 'system' with content `之前的对话摘要：${summary}`. Use the same model (already resolved) for summary generation. Constants: `COMPRESSION_THRESHOLD = 20`, `KEEP_RECENT = 10`.
   - **onStepFinish token recording (per D-382):** Add `onStepFinish` callback (note: AI SDK 7 aliases this to onStepEnd — use onStepFinish for backward compat). Accumulate `stepInputTokens += usage.inputTokens ?? 0` and `stepOutputTokens += usage.outputTokens ?? 0` in closure variables. In the existing onFinish callback, pass these accumulated values to appendMessage's inputTokens/outputTokens fields instead of usage.inputTokens/usage.outputTokens (which only reflect the last step).
   - **consumeStream protection (per D-383):** After calling `streamText()` and before returning the stream, call `result.consumeStream()` (no await — fire-and-forget). This ensures the stream is fully consumed even if the client disconnects, so onFinish fires and the assistant message is persisted. The existing toUIMessageStream + pipeUIMessageStreamToResponse flow remains unchanged.
   - **userId passthrough:** Accept optional `userId` in chat() options and pass it to chatHistory.createConversation().

4. **ai-chat.controller.ts — 3 new endpoints:**
   - `GET /api/ai/conversations` — List conversations with pagination. Query params: page (default 1), pageSize (default 20). Apply `@UseGuards(JwtAuthGuard, AdminGuard)` — admin-only. Return `{ code: 200, data: { list: [...], total, page, page_size }, message: 'ok' }`. Use ChatHistoryService.listConversationsPaged().
   - `GET /api/ai/conversations/:id/messages` — Get messages for a conversation. This endpoint is `@Public()` so the frontend can recover its own conversation after refresh (per D-385). The :id is the Sqids-encoded publicId. Return `{ code: 200, data: [...messages], message: 'ok' }`. Use ChatHistoryService.getConversationMessages().
   - `DELETE /api/ai/conversations/:id` — Delete a conversation. Apply `@UseGuards(JwtAuthGuard, AdminGuard)` — admin-only. The :id is the Sqids-encoded publicId. Return `{ code: 200, data: null, message: 'ok' }`. Use ChatHistoryService.deleteConversation().
   - Import JwtAuthGuard from `../auth/guards/jwt-auth.guard` and AdminGuard from `../common/guards/admin.guard`. These are already used elsewhere in the project.

5. **ai.module.ts — no changes needed** (ChatHistoryService and ChatService are already registered; new controller methods use existing services).

6. **Drizzle migration:** Run `npx drizzle-kit generate` after schema change to create the migration for chat_conversations.userId. Then `npx drizzle-kit push` to apply.

Key constraints:
- Do NOT change the existing POST /api/ai/chat endpoint behavior (same path, same streaming protocol).
- Do NOT add any new npm packages — generateText and consumeStream are already in the 'ai' package.
- The prepareStep callback receives `{ messages }` and can return `{ messages: newMessages }` to replace the message array for the next step.
- consumeStream() is called WITHOUT await — it starts background consumption. The stream returned to the client is the toUIMessageStream, not the raw result.stream.

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| client → POST /api/ai/chat | Untrusted input (anonymous per D-384), already rate-limited |
| client → GET /api/ai/conversations/:id/messages | Public endpoint — any visitor can read any conversation's messages by guessing Sqids IDs |
| admin → GET /api/ai/conversations | Admin-only, requires JWT + AdminGuard |
| admin → DELETE /api/ai/conversations/:id | Admin-only, destructive operation |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation |
|-----------|----------|-----------|----------|-------------|------------|
| T-19-01 | Information Disclosure | GET /conversations/:id/messages (public) | medium | mitigate | Sqids IDs are non-sequential and hard to guess (6+ char encoded). Rate limiting applies. Acceptable for personal blog. |
| T-19-02 | Denial of Service | prepareStep generateText for summary | low | accept | Summary generation only triggers after 20 messages, uses same model, personal blog scale |
| T-19-03 | Tampering | DELETE /conversations/:id | high | mitigate | AdminGuard + JwtAuthGuard — only authenticated admins can delete |
| T-19-SC | Tampering | npm installs | high | mitigate | No new packages added in this plan — all features use existing 'ai' package |
</threat_model>
