  <action>
    Per D-30, D-31, D-33, D-36:

    Install bcryptjs: npm install bcryptjs && npm install -D @types/bcryptjs

    Create TokenService (injectable):
    - Constructor injects SettingsService (from global SettingsModule)
    - generateAccessToken(user: { id: number, userGroupId: number, permissions: number[] }): Promise<string>
      - Read secret from settingsService.get('JWT_SECRET')
      - Encode user.id to public ID via generatePublicID(user.id, EntityType.User)
      - Encode userGroupId to public ID via generatePublicID(userGroupId, EntityType.UserGroup)
      - Create payload: { user_id: publicUserID, user_group_id: publicUserGroupID, permissions: permissions, iss: "anheyu-app", iat: now-seconds, exp: now+900-seconds (15min), nbf: now-seconds }
      - Sign with HS256 using jsonwebtoken directly (not JwtService, because we need dynamic secret per call)
    - generateRefreshToken(userId: number): Promise<string>
      - Read secret from settingsService.get('JWT_SECRET')
      - Encode userId to public ID
      - Create payload: { user_id: publicUserID, iss: "anheyu-app", iat: now-seconds, exp: now+2592000-seconds (30 days), nbf: now-seconds }
      - NO user_group_id, NO permissions in refresh token
      - Sign with HS256
    - generateSessionTokens(user: { id, userGroupId, permissions }): Promise<{ accessToken: string, refreshToken: string, expires: number }>
      - Generate both tokens, compute expires as (now + 15min).getTime() (millisecond timestamp)
    - refreshAccessToken(refreshToken: string): Promise<{ accessToken: string, expires: number }>
      - Verify refresh token with dynamic secret
      - Decode claims.user_id via decodePublicID, verify entityType === EntityType.User
      - Look up user by dbID in database (inject DRIZZLE)
      - Verify user exists and status === 1 (Active)
      - Generate new access token with user's current userGroupId and permissions
      - Return { accessToken, expires }

    Modify JwtStrategy to use dynamic secret:
    - Change constructor to inject SettingsService instead of ConfigService
    - Use secretOrKeyProvider: (request, rawJwtToken, done) => { const secret = this.settingsService.get('JWT_SECRET'); done(null, secret || 'change-me-in-production'); }
    - This replaces the static secretOrKey from ConfigService
    - Extend validate() to return full payload: { user_id, user_group_id, permissions, iss, iat, exp, nbf }
    - Keep existing check: if no user_id or user_group_id, throw UnauthorizedException

    Update AuthModule:
    - Remove JwtModule.registerAsync (TokenService signs tokens directly with jsonwebtoken, not JwtService)
    - Keep PassportModule.register({ defaultStrategy: 'jwt' })
    - Add providers: [JwtStrategy, AuthService, TokenService]
    - Add controllers: [AuthController]
    - Import SettingsModule (already global, but explicit import for clarity)
    - Inject DRIZZLE for database access in TokenService

    IMPORTANT: TokenService must use the jsonwebtoken library directly (import * as jwt from 'jsonwebtoken') for signing, NOT JwtService from @nestjs/jwt. JwtService uses a static secret configured at module registration, but we need dynamic secret per D-30. The jsonwebtoken library allows passing secret as a parameter to each sign/verify call.

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Client -> Auth API | Untrusted credentials and tokens from client |
| AuthService -> Database | Trusted internal; Drizzle parameterized queries |
| TokenService -> SettingsService | Trusted internal; JWT_SECRET from settings cache |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-02-06 | Spoofing | POST /api/auth/login | critical | mitigate | bcryptjs.compare prevents password guessing; rate limiting per D-37 |
| T-02-07 | Tampering | JWT token forgery | critical | mitigate | HS256 signing with dynamic secret from settings; secret never exposed to client |
| T-02-08 | Information Disclosure | JWT_SECRET exposure | critical | mitigate | Secret stored in settings table, never in env vars or client code; SettingsService public/private filtering |
| T-02-09 | Spoofing | Token replay | medium | mitigate | Short access token TTL (15min) per D-31; refresh token does not rotate (matches Go behavior) |
| T-02-10 | Elevation | Forged admin claims | high | mitigate | AdminGuard decodes user_group_id via Sqids and checks dbID === 1; claims cannot be forged without JWT_SECRET |
| T-02-11 | Tampering | Brute force login | high | mitigate | @nestjs/throttler rate limiting: 5 requests per 10 seconds on login per D-37 |
| T-02-SC | Tampering | npm install (bcryptjs) | low | accept | bcryptjs is [OK] in legitimacy audit; pure JS, no native compilation |
</threat_model>
