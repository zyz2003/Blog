    **Part A — Comment export/import stale 404 (2 test fixes):**
    In server/test/api-compat/comment-api-compat.spec.ts, locate the two describe blocks around lines 265-287: "POST /api/comments/export" and "POST /api/comments/import". These tests currently expect 404 because the endpoints were not implemented when the tests were written in Phase 11. The endpoints are now implemented (comment-admin.controller.ts has @Post('export') and @Post('import') handlers). Update both tests:
    - For export test: Change the test name from "returns 404 for unimplemented export" to "returns success response for export". Change `expect(res.status).toBe(404)` to `assertSuccessResponse(res)` (import assertSuccessResponse from helpers if not already imported). The export endpoint returns a JSON file download with attachment header, so verify status 200 and that response has Content-Disposition header containing "comments_export".
    - For import test: Change the test name from "returns 404 for unimplemented import" to "returns success response for import". Change `expect(res.status).toBe(404)` to verify the endpoint returns 200 with a result object containing imported/skipped/error_count fields. Send a valid multipart form with a JSON file containing an empty array `[]` to test the import endpoint. The import handler expects a file upload via @UseInterceptors(FileInterceptor('file')), so use `.attach('file', Buffer.from('[]'), 'comments.json')` in supertest.
    - Remove the stale comments saying "Note: export/import endpoints are not implemented" and "route not found".

    **Part B — Auth refresh-token test isolation (2 test fixes):**
    In server/test/api-compat/auth-api-compat.spec.ts, the refresh-token tests (lines 184-240) fail in batch runs because they rely on ctx.adminToken which may be invalidated by DB state changes from other test files. The fix: each refresh-token test already generates a fresh login to get a refreshToken (lines 187-189 and 211-213). The issue is that the login itself may fail if the admin user's JWT_SECRET or password hash has been corrupted by prior test runs. Add a safety check: before the refresh tests, re-seed the admin user by calling the same seeding logic used in createTestApp. Specifically, in the "POST /api/auth/refresh-token -- dual-channel" describe block, add a beforeAll that ensures the admin user exists with the correct password by upserting into the DB using ctx.db. This mirrors the seedBaseData pattern from api-compat-helpers.ts. Alternatively, if the login calls already work in isolation, the simpler fix is to ensure the auth-api-compat test file is self-contained by adding a fresh createTestApp call within the refresh-token describe block (not sharing ctx with other tests). However, since the file already uses a single ctx, the minimal fix is to add a login retry or re-seed before the refresh tests.
