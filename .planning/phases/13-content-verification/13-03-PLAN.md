    FIRST: Fix the three structural mismatches in server/src/file/file.service.ts.

    Fix 1 — Pagination field naming (RESEARCH Pitfall 1, MEDIUM risk #54):
    In getFilesByPath method (around line 98-106), change the pagination object from { page, pageSize, total } to { page, page_size, next_token, is_cursor } per Go Pagination struct. Remove total from pagination (it belongs in props, which already has it). Set page_size to the pageSize parameter value. Set is_cursor to true (Go uses cursor-based pagination). Set next_token to empty string for the current page, but do NOT include next_token when there are no more pages (matching Go's omitempty behavior — Go omits next_token entirely when empty). This prevents frontend "load more" from showing incorrectly when there are no more files. The Go Pagination struct from _go-backend-archive/pkg/domain/model/file.go lines 184-197 defines: Page int (json:"page"), PageSize int (json:"page_size"), NextToken string (json:"next_token,omitempty"), IsCursor bool (json:"is_cursor").

    Fix 2 — toFileItem date serialization (RESEARCH Pitfall 2, LOW risk):
    In toFileItem method (around line 806-833), import toISODateString from ../../common/utils/time.util and change created_at: file.createdAt to created_at: toISODateString(file.createdAt), and updated_at: file.updatedAt to updated_at: toISODateString(file.updatedAt). This matches the pattern used in article.service.ts, page.service.ts, and other modules.

Per Go FileItem struct lines 146-147: Permission interface{} (json:"permission") is nil, Capability string (json:"capability") is empty string.
