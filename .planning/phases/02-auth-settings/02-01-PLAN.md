## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Client -> Settings API | Untrusted input via request body (keys array, key-value pairs) |
| SettingsService -> Database | Trusted internal; Drizzle parameterized queries prevent injection |
| SettingsService -> Filesystem | Backup writes to data/backups/; path traversal risk |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-02-01 | Information Disclosure | GET /api/settings/get-by-keys | high | mitigate | Public/private key filtering: non-admin users cannot access JWT_SECRET, SMTP credentials, CDN secrets per D-39 |
| T-02-02 | Tampering | POST /api/settings/update | high | mitigate | AdminGuard restricts writes to admin users only; class-validator validates input structure |
| T-02-03 | Information Disclosure | AI profiles API keys | critical | mitigate | maskAIProfiles() masks all API keys before returning; preserve existing on update per D-42 |
| T-02-04 | Tampering | POST /api/settings/get-by-keys keys array | medium | mitigate | class-validator validates keys is non-empty string array; no SQL injection via Drizzle |
| T-02-05 | Elevation | Non-admin accessing admin settings | medium | mitigate | Controller checks admin status via decodePublicID(user.user_group_id) before passing isAdmin to service |
| T-02-SC | Tampering | npm install (date-fns, date-fns-tz) | low | accept | Both packages are widely used, well-maintained, [OK] in legitimacy audit |
