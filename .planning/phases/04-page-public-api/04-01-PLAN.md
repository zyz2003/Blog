    Implement normalizePath as a standalone exported function (not method) matching Go normalizePath exactly per D-76: trim whitespace, if empty return empty, if not starting with / prepend /, if length > 1 and ending with / strip trailing /.

    Implement validatePath as a private method matching Go validatePath per D-79: throw BadRequestException with Chinese messages for empty path, path not starting with /, path containing space, path containing any of the special characters: < > " ' & ? # = + ;

    Implement splitContentAndCustomJS as a standalone exported function per D-83: use regex pattern matching Go's (?is)<script[^>]*>(.*?)</script> — in JS use /<script[^>]*>([\s\S]*?)<\/script>/gi. Find all matches, extract group 1 (script content), trim each, join with double newline. Replace all script tags in content, trim result. Return { content: cleanContent, customJs: scripts.join('\n\n') }.

    Implement service methods:
    - create(options): normalizePath on options.path, validatePath, check existsByPath (throw ConflictException with PAGE_PATH_EXISTS if exists), call repo.create with options, return created page
    - getById(id: number): call repo.findById, throw NotFoundException with PAGE_NOT_FOUND if null, return page
    - getByPath(path: string): normalizePath, call repo.findByPath. If null and path !== '/', try path + '/' as fallback per D-76. If still null, throw NotFoundException with PAGE_NOT_FOUND. Return page

    - update(id: number, options): getById first (throws if not found). If options.path provided, normalize it. If path changed from current, validatePath and check existsByPath with excludeId=id. Call repo.update with only provided fields (filter out undefined). Return updated page
    - delete(id: number): call repo.softDelete per D-81
    - initializeDefaultPages(): replicate Go InitializeDefaultPages per D-82. Define 3 default page objects with exact content from Go source (privacy with full Chinese content + embedded script, cookies with full Chinese content, copyright with full Chinese content). First loop: process privacy page — call splitContentAndCustomJS on markdownContent, then on content, set customJs from markdown script (fallback to content script). Second loop: for each default page, check if exists by path via repo.findByPath. If exists and is /privacy with empty customJs, run migration per D-85: split scripts from existing markdownContent and content, update page with extracted scripts. If not exists, create via repo.create. All operations must be idempotent per D-84.

Use the same toApiResponse pattern as ArticleService for snake_case JSON serialization: map DB camelCase fields to snake_case (id, title, path, content, markdown_content, custom_js, custom_css, description, is_published, show_comment, sort, created_at, updated_at).
