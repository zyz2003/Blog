    - CreateUploadSessionDto: uri (string, required), size (number, required, >= 0), policy_id (string, required, Sqids public ID), overwrite (boolean, optional, default false)
    - FinalizeUploadDto: uri (string, required), policy_id (string, required), size (number, required)

    Create UploadService in server/src/file/upload.service.ts. Inject DRIZZLE and StoragePolicyService. Use @Inject(forwardRef(() => ThumbnailService)) for ThumbnailService injection to resolve circular dependency with FileModule/ThumbnailModule.

    **URI Parser** — delegate to parseAnzhiyuURI from utils/path-resolver.ts

    **Session Map** (private property):
    In-memory Map<string, UploadSession> per D-94. Add a 60-second interval (setInterval) that scans all sessions and removes expired ones (expireAt < Date.now()). Clear interval in OnModuleDestroy.

    **Startup Cleanup** (OnModuleInit):
    Scan data/uploads/tmp/ directory for subdirectories older than 24 hours and delete them per D-95 using cleanupExpiredTempDirs.

    **CreateUploadSession** (createSession method):
    1. Parse URI via parseAnzhiyuURI to extract path and fileName
    2. Decode policy_id with EntityType.StoragePolicy to get policy DB ID
    3. Look up policy via StoragePolicyService (throw 404 with STORAGE_NOT_FOUND if not found)
    4. Validate policy.type is 'local' (throw 400 with INVALID_POLICY_TYPE if not)
    5. Validate fileSize against policy.maxSize (0=unlimited per D-100). Throw 400 if exceeds
    6. In a Drizzle transaction:
       - Call findOrCreateParentPath to ensure parent directories exist (create file records with type=2 for missing directories)
       - If overwrite=false, check for existing file at same parentId+name in files table. If exists, throw 409 with UPLOAD_FILE_EXISTS per RESEARCH Pitfall 4
       - Create temp entity record in entities table with: size=fileSize, policyId, createdBy=ownerId, uploadSessionId=sessionId, type='file_content'
    7. Determine chunkSize from policy.settings.chunk_size (default 5MB = 5242880)
    8. Generate UUID session ID
    9. Store session in Map with 24h TTL
    10. Return UploadSessionData per RESEARCH Section 2: { expires: Math.floor(expireAt/1000), upload_method: 'server', session_id, chunk_size, storage_policy: { id: policyPublicID, name: policy.name, type: policy.type, max_size: policy.maxSize } }

    **UploadChunk** (uploadChunk method):
    1. Look up session in Map. If not found, throw 404 with UPLOAD_SESSION_NOT_FOUND
    2. Verify ownerId matches (throw 403 with UPLOAD_SESSION_NOT_OWNER if mismatch)
    3. Calculate totalChunks = Math.ceil(session.fileSize / session.chunkSize) per RESEARCH Pitfall 2
    4. Validate index in [0, totalChunks). Throw 400 with UPLOAD_SESSION_INVALID_CHUNK if invalid
    5. Create temp directory data/uploads/tmp/{sessionId}/ if not exists
    6. Write chunk body to data/uploads/tmp/{sessionId}/chunk-{index} (raw binary, use fs.writeFile)
    7. Update session: add index to uploadedChunks Set
    8. Check if ALL chunks uploaded (uploadedChunks.size === totalChunks):
       - If yes: call completeFileUpload (merge + finalize)
       - If no: return null (success, wait for more chunks)
    9. Return null

    **completeFileUpload** (private method, triggered automatically after last chunk):
    1. Create output file path. For local storage: policy.basePath + URI path (ensure parent dirs exist via ensureDirectoryExists)
    2. Merge chunks via mergeChunkFiles: sequentially read each chunk file and append to target file
    3. In a Drizzle transaction:
       - Update temp entity: set source=targetFilePath, mimeType=inferred from extension, size=actual merged file size, clear uploadSessionId
       - Create or update file record in files table: ownerId, parentId, name=fileName, size, type=1 (file), primaryEntityId=tempEntity.id. If overwrite=true and file existed, update the existing file's primaryEntityId
    4. Delete session from Map
    5. Clean up temp directory (delete data/uploads/tmp/{sessionId}/ and all contents)
    6. **Trigger thumbnail generation**: call ThumbnailService.generateThumbnail(fileId, entity.source, fileName) per D-103. Wrap in try-catch; log error but do not throw on failure per D-106
    7. Return completion info (for auto-merge case, this is internal; for FinalizeClientUpload, return { file_id, name, size })

    **GetUploadSessionStatus** (getSessionStatus method):
    1. Look up session in Map
    2. If not found, return { is_valid: false } with 404 status per RESEARCH Section 2
    3. If ownerId mismatch, return { is_valid: false } with 403
    4. Return { session_id, is_valid: true, chunk_size, total_chunks: ceil(fileSize/chunkSize), uploaded_chunks: Array.from(uploadedChunks).sort(), expires_at: expireAt.toISOString() }

    **DeleteUploadSession** (deleteSession method):
    1. Look up session in Map, verify ownership
    2. Clean up temp directory on disk (data/uploads/tmp/{sessionId}/)
    3. Hard-delete temp entity from entities table (where id = session.tempEntityId)
    4. Delete session from Map
    5. Return null

    **FinalizeClientUpload** (finalizeClientUpload method):
    Per D-97/D-98, this is rarely used for local storage but preserved for API compatibility.
    1. Parse URI, get policy
    2. Verify file exists on disk at expected path
    3. In a transaction: create entity record + file record (same as completeFileUpload step 3)
    4. Trigger thumbnail generation (same try-catch pattern as completeFileUpload step 6)
    5. Return { file_id: Sqids-encoded file ID, name, size }
