## Objective

Create a Node.js CLI script (`scripts/migrate.ts`) that reads data from the Go backend's SQLite database and writes it to the NestJS backend's SQLite database, preserving all data integrity including id_seed and JWT_SECRET.

### Task 2: Create timestamp conversion utility

**File:** `scripts/migrate-utils.ts`

1. **`convertGoTimeToEpoch(goTime: string | number | null): number | null`**
   - Input: Go Ent's ISO8601/RFC3339 text (e.g., `"2025-07-13T23:40:12+08:00"`, `"2025-07-13T23:40:12Z"`)
   - Output: Unix epoch integer (seconds) or null if input is null/empty
   - Handle edge cases:
     - `null` or `undefined` → `null`
     - Empty string → `null`
     - Already a number (Go may store as integer in some SQLite setups) → pass through
     - Invalid date → log warning, return `null`

2. **`convertRow(row: Record<string, any>, timestampColumns: string[]): Record<string, any>`**
   - Iterate over timestampColumns in the row
   - Apply `convertGoTimeToEpoch` to each
   - Return transformed row (non-timestamp columns pass through unchanged)

3. **`backupDatabase(dbPath: string): string`**
   - Copy dbPath to `{dbPath}.backup.{timestamp}`
   - Return backup path
   - Use `fs.copyFileSync`

4. **`restoreBackup(backupPath: string, targetPath: string): void`**
   - Copy backup back to target
   - Log restoration

5. **`formatProgress(current: number, total: number, tableName: string): string`**
   - Return formatted progress string like `[15/33] Migrating articles...`

**Verification:** Run `npx tsx scripts/test-convert.ts` with test pairs:
- `"2025-07-13T23:40:12Z"` → `1752450012`
- `null` → `null`
- `""` → `null`
- `1752450012` (already integer) → `1752450012`
- `"2024-01-15T08:30:00Z"` → `1705302600`

### Task 3: Create main migration script

**File:** `scripts/migrate.ts`

1. **CLI argument parsing** (manual, no extra deps):
   - `--source <path>` — Source Go SQLite .db path (required)
   - `--target <path>` — Target NestJS SQLite .db path (required)
   - `--skip-backup` — Skip auto-backup (default: false)
   - `--skip-verify` — Skip post-migration verification (default: false)
   - `--verbose` — Verbose logging (default: false)
   - Validate: source file must exist, target directory must exist

2. **Migration flow**:
   ```
   1. Parse args
   2. Open source DB (better-sqlite3, readonly)
   3. Open target DB (better-sqlite3, readwrite)
   4. If not --skip-backup: backup target DB
   5. Disable FK checks on target (PRAGMA foreign_keys=OFF)
   6. For each table in migration order:
      a. Read all rows from source table (SELECT * FROM {sourceTable})
      b. Transform rows (timestamp conversion, column pass-through)
      c. Clear target table (DELETE FROM {targetTable})
      d. Insert rows into target table (single pass — FK checks disabled)
      e. Log progress
   7. Re-enable FK checks on target (PRAGMA foreign_keys=ON)
   8. If not --skip-verify: run verification
   9. Close both DBs
   10. Log completion summary
   ```

3. **Self-referencing table strategy**: Since FK checks are disabled during the entire migration (step 5-7), self-referencing tables (comments, files) can be inserted in a single pass. No two-pass approach needed. FK integrity is verified in the post-migration check (step 8).

4. **Error handling**:
   - If any table migration fails: log error, restore backup, exit with code 1
   - If verification fails: log failures, exit with code 2 (don't restore — data may be partially correct)
   - Wrap entire flow in try/catch

5. **Row transformation per table**:
   - Get timestamp columns for current table from config
   - Apply `convertRow()` for timestamp conversion
   - All other columns pass through unchanged (same names, same types)
   - For pivot tables with name mapping: read from Go name, write to NestJS name

6. **Insertion strategy**:
   - Use `INSERT OR REPLACE INTO` to handle potential conflicts
   - Batch inserts in transactions (every 100 rows) for performance

**Verification:** `npx tsx scripts/migrate.ts --help` shows usage. Create a minimal test source .db with 1 row in user_groups and settings, run migration, verify target .db has the data.

### Task 4: Create post-migration verification + npm scripts + docs

1. **`verifyMigration(source, target): VerificationResult`** (in `scripts/migrate.ts`)
   
   a. **Row count check** — For each table:
      - `SELECT COUNT(*) FROM {table}` on both source and target
      - Compare counts
      - Log any mismatches
   
   b. **Critical value spot-check**:
      - Read `id_seed` from source settings → compare with target
      - Read `JWT_SECRET` from source settings → compare with target
      - These must be exact string matches
   
   c. **FK integrity check**:
      - `PRAGMA foreign_key_check` on target DB
      - Log any violations
   
   d. **Return result**: `{ passed: boolean, failures: string[] }`

2. **Output format**:
   ```
   ✅ user_groups: 3 rows (source: 3)
   ✅ settings: 45 rows (source: 45)
   ✅ id_seed: matches
   ✅ JWT_SECRET: matches
   ❌ articles: 120 rows (source: 125) — MISMATCH
   ✅ FK integrity: no violations
   ```

3. **Add to `server/package.json`**:
   ```json
   "migrate": "tsx ../scripts/migrate.ts",
   "migrate:dry-run": "tsx ../scripts/migrate.ts --skip-backup --skip-verify --verbose"
   ```

4. **Create `scripts/README.md`** with usage instructions, example commands, migration flow description, troubleshooting.

## Edge Cases

1. **Source DB has tables that NestJS doesn't have** — Skip with warning
2. **NestJS DB has tables that source doesn't have** — Skip (leave empty)
3. **NULL values in timestamp columns** — Convert to NULL (not 0)
4. **Go timestamps already stored as integers** — Pass through unchanged
5. **Large tables (visitor_logs, url_stats)** — Batch insert in transactions
6. **Empty source tables** — Skip with info log
