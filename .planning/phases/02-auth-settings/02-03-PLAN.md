    Create UserService (injectable):
    - Constructor injects DRIZZLE, SettingsService (for Gravatar URL)
    - getUserInfo(userId: number): Promise<UserInfoResponse>
      - Query user by id from database (join with userGroups)
      - Build response:
        - id: generatePublicID(user.id, EntityType.User) — public ID string
        - created_at, updated_at: formatToChinaTime()
        - username, nickname, email, website from user
        - avatar: process URL — if not starts with "http://" or "https://", prepend Gravatar base URL WITH slash trimming (gravatarBaseURL.trimEnd('/') + '/' + avatar.trimStart('/')). This matches Go's GetUserInfo behavior per RESEARCH.md Compatibility Note 4.

        - userGroup: { id: generatePublicID(group.id, EntityType.UserGroup), name, description }
        - status: user.status
    - updatePassword(userId: number, oldPassword: string, newPassword: string): Promise<void>
      - Look up user by id, get passwordHash
      - Verify: bcryptjs.compare(oldPassword, user.passwordHash). If false, throw UnauthorizedException("旧密码不正确")
      - Hash new password: bcryptjs.hash(newPassword) — use default cost (10) matching Go
      - Update user.passwordHash in database
    - updateProfile(userId: number, nickname?: string, website?: string): Promise<void>
      - Update user nickname and/or website in database
    - adminListUsers(page: number, pageSize: number, keyword?: string, groupID?: number, status?: number): Promise<AdminListUsersResponse>
      - Build query with filters: keyword (ILIKE on username/nickname/email), groupID, status
      - For keyword search in SQLite, use LIKE with %keyword% (SQLite does not have ILIKE, use LOWER() or LIKE)
      - Paginate with LIMIT and OFFSET
      - Build AdminUserDTO for each user:
        - id: generatePublicID(user.id, EntityType.User) — public ID
        - created_at, updated_at: formatToChinaTime()
        - username, nickname, email, website, avatar, lastLoginAt, status
        - avatar: non-http avatar prepends Gravatar URL WITHOUT slash trimming (just gravatarBaseURL + avatar). This matches Go's AdminListUsers behavior per RESEARCH.md Compatibility Note 4.
        - userGroupID: generatePublicID(user.userGroupId, EntityType.UserGroup) — PUBLIC ID (string!). This is DIFFERENT from GetUserInfo where userGroupID is raw DB ID number.
        - userGroup: { id, name, description } with public ID
      - Return { users: AdminUserDTO[], total, page, size }
    - adminCreateUser(dto: AdminCreateUserDto): Promise<AdminUserDTO>
      - Hash password with bcryptjs (default cost)
      - Insert user into database
      - Return AdminUserDTO of created user
    - adminUpdateUser(publicId: string, dto: AdminUpdateUserDto): Promise<void>
      - Decode public ID to get dbID and verify entityType === EntityType.User
      - If dto includes userGroupID, decode it from public ID too
      - Update user in database
    - adminDeleteUser(publicId: string): Promise<void>
      - Decode public ID, soft-delete user (set deletedAt to current time)
    - adminResetPassword(publicId: string, newPassword: string): Promise<void>
      - Decode public ID, hash new password, update user.passwordHash
    - adminUpdateStatus(publicId: string, status: number): Promise<void>
      - Decode public ID, update user.status
    - getUserGroups(): Promise<UserGroupDTO[]>
      - Query all user groups
      - Return array of { id: generatePublicID(group.id, EntityType.UserGroup), name, description }

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Client -> User API | Untrusted input (profile data, passwords, admin operations) |
| UserService -> Database | Trusted internal; Drizzle parameterized queries |
| Admin endpoints | Only admin users (dbID===1) can access |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-02-12 | Tampering | POST /api/user/update-password | high | mitigate | bcryptjs.compare verifies old password before update; class-validator validates input |
| T-02-13 | Elevation | Admin user management endpoints | high | mitigate | AdminGuard restricts to admin users; public ID decoding prevents direct DB ID manipulation |
| T-02-14 | Information Disclosure | GET /api/user/info | low | mitigate | Users can only access their own info (user_id from JWT, not request param) |
| T-02-15 | Spoofing | Admin create user with existing email | medium | mitigate | Database unique constraint on email prevents duplicates |
| T-02-16 | Tampering | Admin delete user | high | mitigate | AdminGuard required; soft-delete prevents permanent data loss |
</threat_model>
