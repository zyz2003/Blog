**Do NOT re-read NestJS controller files** — Plan 01 Task 3 already cross-referenced all frontend endpoints against NestJS controllers and produced the Cross-Reference Gap Summary in 12-API-INVENTORY.md. Use that summary as the NestJS status source.

Risk grading criteria (Claude's discretion per CONTEXT.md):

**HIGH risk** -- Response format likely incompatible:
- Field type mismatch (number vs string, null vs non-null)
- Missing or extra fields in response
- Different nesting structure
- Endpoint implemented in Go but 501 in NestJS
- Date format difference that breaks frontend parsing

**MEDIUM risk** -- Response format possibly incompatible:
- Field nullability difference (Go never null, NestJS can be null)
- Value format difference (e.g., description: "" vs null)
- Pagination structure difference
- Error message wording difference

**LOW risk** -- Minor difference unlikely to break frontend:
- Date precision difference (RFC3339 vs ISO 8601)
- Response field ordering difference
- Non-functional header difference

**NONE risk** -- Verified compatible:
- Test passes with field-by-field verification
- Go and NestJS use identical response structure

For each module in the inventory, read the corresponding Go handler source in _go-backend-archive/pkg/handler/ and compare with NestJS DTO definitions (not full controller source — that was already cross-referenced in Plan 01). Focus on:
1. Response DTO structure (field names, types, nesting)
2. Request DTO structure (field names, required/optional)
3. Error response format (status codes, message format)
4. Special behaviors (pagination, filtering, sorting)

Start with auth and settings modules (already deeply analyzed in RESEARCH.md and verified in Plans 02-03). For these, use test results to confirm or adjust risk levels.

For other modules (article, page, file, comment, links, album, doc-series, music, storage, user, statistics, theme), do a quicker scan: read Go handler, compare response struct with NestJS DTO, mark risk based on structural differences.

Known HIGH risks from research:
1. expires format: Go returns int64 (number), NestJS returns string -- HIGH
2. 5 auth endpoints: Go implemented, NestJS 501 -- HIGH
3. created_at/updated_at: Go time.Time (never null), NestJS can be null -- MEDIUM
4. Settings update body: test was using wrong format -- verify from Plan 03 results

Known MEDIUM risks:
5. userGroup.description: Go string (zero value ""), NestJS string|null -- MEDIUM
6. Captcha provider edge cases -- MEDIUM
7. getByKeys non-admin filtering logic difference -- MEDIUM

Produce a table per module with columns: Endpoint, Risk Level, Issue Description, Go Behavior, NestJS Behavior, Phase to Fix.
