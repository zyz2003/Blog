## Tasks

### Task 1: Implement 4 on-demand dispatch jobs

**What:** Create 4 on-demand job classes that are dispatched via `ScheduleService.dispatch()` (fire-and-forget Promise pattern per D-222).

**Files:**
- `server/src/schedule/jobs/thumbnail-generation.job.ts`
- `server/src/schedule/jobs/comment-notification.job.ts`
- `server/src/schedule/jobs/link-cleanup.job.ts`
- `server/src/schedule/jobs/cleanup-orphaned-items.job.ts`
- `server/src/schedule/jobs/index.ts` — update barrel export

**How:**

Each on-demand job is NOT registered with `@Cron()`. Instead, they expose a `run()` method called by `ScheduleService.dispatch()`.

1. **ThumbnailGenerationJob:**
   ```typescript
   export class ThumbnailGenerationJob {
     constructor(private readonly thumbnailService: ThumbnailService) {}
     async run(fileId: number): Promise<void> {
       await this.thumbnailService.generateThumbnail(fileId, ...);
     }
   }
   ```
   - 5-minute timeout
   - Matches Go: `ThumbnailGenerationJob.Run()` calls `thumbnailService.Generate(ctx, fileID)`

2. **CommentNotificationJob:**
   ```typescript
   export class CommentNotificationJob {
     constructor(
       private readonly emailService: EmailService,
       private readonly notificationService: NotificationService,
       private readonly commentRepository: CommentRepository,
     ) {}
     async run(newCommentId: number): Promise<void> {
       const comment = await this.commentRepository.findById(newCommentId);
       if (!comment) return;
       // If reply to parent, send email notification to parent commenter
       if (comment.parentId) {
         const parent = await this.commentRepository.findById(comment.parentId);
         if (parent?.email) {
           await this.emailService.sendCommentNotification(comment, parent);
         }
       }
       // Also trigger in-app notification (existing NotificationService path)
       // This is handled by CommentService.fireCommentReplyNotification() already
     }
   }
   ```
   - Matches Go: fetches comment, checks for parent, sends notification email
   - **Dual notification:** email (new, matching Go) + in-app (existing via NotificationService)

3. **LinkCleanupJob:**
   ```typescript
   export class LinkCleanupJob {
     constructor(
       private readonly linkRepository: LinkRepository,
       private readonly settingsService: SettingsService,
       @Inject(DRIZZLE) private readonly db: any,
     ) {}
     async run(): Promise<void> {
       // Get protected category IDs from settings
       const defaultCategoryId = this.settingsService.get('FRIEND_LINK_DEFAULT_CATEGORY');
       const excludeIds = defaultCategoryId ? [parseInt(defaultCategoryId)] : [2]; // fallback to 2
       // Delete unused categories (excluding protected)
       await this.db.delete(linkCategories).where(
         and(isNull(linkCategories.deletedAt), notInArray(linkCategories.id, excludeIds), /* no links reference */)
       );
       // Delete unused tags
       await this.db.delete(linkTags).where(/* no link_tag_pivot references */);
     }
   }
   ```
   - Matches Go: `LinkCleanupJob.Run()` deletes unused link_categories (excluding default) and link_tags

4. **CleanupOrphanedItemsJob:**
   ```typescript
   export class CleanupOrphanedItemsJob {
     constructor(@Inject(DRIZZLE) private readonly db: any) {}
     async run(): Promise<{ deletedTags: number; deletedCategories: number }> {
       // Delete post_tags with no article references
       const deletedTags = await this.db.delete(postTags).where(/* no article_post_tags reference */);
       // Delete post_categories with no article references
       const deletedCategories = await this.db.delete(postCategories).where(/* no article_post_categories reference */);
       return { deletedTags, deletedCategories };
     }
   }
   ```
   - Matches Go: `CleanupOrphanedItemsJob.Run()` calls `cleanupSvc.CleanupOrphanedItems()`

**Note:** These jobs are NOT registered as providers with `@Cron()`. They are instantiated and called by `ScheduleService.dispatch()`.

**Verify:** Each job can be dispatched via ScheduleService and completes without error.

### Task 2: Add dispatch methods to ScheduleService

**What:** Add typed dispatch methods for each on-demand job, matching Go backend's `DispatchXxx` methods in broker.go.

**Files:**
- `server/src/schedule/schedule.service.ts` — add 4 dispatch methods

**How:**

```typescript
dispatchThumbnailGeneration(fileId: number): void {
  const job = this.moduleRef.get(ThumbnailGenerationJob, { strict: false });
  this.dispatch('ThumbnailGenerationJob', () => job.run(fileId));
}

dispatchCommentNotification(commentId: number): void {
  const job = this.moduleRef.get(CommentNotificationJob, { strict: false });
  this.dispatch('CommentNotificationJob', () => job.run(commentId));
}

dispatchLinkCleanup(): void {
  const job = this.moduleRef.get(LinkCleanupJob, { strict: false });
  this.dispatch('LinkCleanupJob', () => job.run());
}

dispatchOrphanCleanup(): void {
  const job = this.moduleRef.get(CleanupOrphanedItemsJob, { strict: false });
  this.dispatch('CleanupOrphanedItemsJob', () => job.run());
}
```

Alternative: Inject job dependencies directly into ScheduleService and create inline closures (simpler, avoids ModuleRef).

**Verify:** Calling `scheduleService.dispatchThumbnailGeneration(5)` runs the job asynchronously without blocking.

### Task 3: Add dispatch hooks in existing services

**What:** Wire on-demand dispatch calls into existing service methods that trigger background tasks.

**Files:**
- `server/src/file/upload.service.ts` — dispatch thumbnail generation after file upload
- `server/src/comment/comment.service.ts` — dispatch comment notification after comment creation
- `server/src/link/link.service.ts` — dispatch link cleanup after link deletion
- `server/src/article/article.service.ts` — dispatch orphan cleanup after article tag/category changes

**How:**

1. **UploadService** — after `completeFileUpload()`, add:
   ```typescript
   this.scheduleService.dispatchThumbnailGeneration(file.id);
   ```
   Matches Go: `articleSvc.UploadArticleImage()` dispatches `ThumbnailGenerationJob`

2. **CommentService** — after `create()`, add:
   ```typescript
   this.scheduleService.dispatchCommentNotification(newComment.id);
   ```
   Matches Go: `commentSvc.Create()` dispatches `CommentNotificationJob`
   But only for reply comments (parentId exists), matching Go logic.

3. **LinkService** — after `adminDeleteLink()` or `batchDeleteLinks()`, add:
   ```typescript
   this.scheduleService.dispatchLinkCleanup();
   ```
   Matches Go: `linkSvc.Delete()` dispatches `LinkCleanupJob`

4. **ArticleService** — after `update()` or `delete()` when tags/categories change, add:
   ```typescript
   this.scheduleService.dispatchOrphanCleanup();
   ```
   Matches Go: article changes dispatch `CleanupOrphanedItemsJob`

5. Inject `ScheduleService` into each of these services. **Circular dependency handling:**
   - ScheduleModule is `@Global()` but also imports feature modules → potential circular dependency
   - **Solution:** Use `@Inject(forwardRef(() => ScheduleService))` + `forwardRef(() => ScheduleModule)` in the importing module
   - Alternative: Use NestJS `ModuleRef.get()` for lazy resolution in dispatch methods
   - Prefer `forwardRef()` as it's the established NestJS pattern (already used in ArticleService for RssService)

**Verify:** File upload triggers thumbnail generation; comment creation triggers notification; link deletion triggers cleanup.

## Execution Notes

- **Fire-and-forget pattern:** All dispatch calls use `ScheduleService.dispatch()` which creates unawaited Promises. This matches D-222.
- **Circular dependency handling:** ScheduleService is `@Global()`, so it can be injected anywhere. If forward references are needed, use `@Inject(forwardRef(() => ScheduleService))`.
- **SettingsService.autoBackup()** will be superseded by the proper BackupService in Plan 10-03. The old autoBackup can be removed or kept as a simple fallback.
- **LinkCleanupJob SQL** needs careful implementation — must check that no `link_tag_pivot` rows reference a tag before deleting it, and no links reference a category before deleting it.
