<objective>
Build the framework-agnostic tool definition layer: ToolDef type (Zod schema + pure execute) and two article tools (search_articles, get_article). These tools call existing domain services (SearchService, ArticleService) via a ToolContext.getService abstraction, never importing any AI library. This is the migration-protected asset that survives a future LangGraph switch unchanged.

Purpose: AI-03 requires framework-agnostic tool definitions. The ToolDef + article-tools layer is the single most valuable migration asset — AI SDK's `tool()` and LangGraph's `tool()` both consume this format, so it must have zero AI library coupling. Per D-350, tools resolve domain services via ToolContext.getService instead of direct db queries, keeping tool logic reusable and tested.

Output: tool-def.ts (ToolDef + ToolContext types), article-tools.ts (searchArticlesTool + getArticleTool + articleTools array), unit tests proving framework independence and correct domain service delegation.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| LLM → tool execute | AI model calls tool with untrusted args (keyword/id strings). Zod schema validates input before execute runs. |
| tool execute → domain service | Tool calls SearchService/ArticleService which are already tested and guarded. No new trust boundary. |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-17-01 | Tampering | searchArticlesTool inputSchema | medium | mitigate | Zod schema enforces keyword:string + limit:int 1-10, rejects non-string/oversized inputs before execute |
| T-17-02 | Information Disclosure | getArticleTool.execute content truncation | low | accept | D-351 truncates to 3000 chars — prevents dumping full article body to LLM context, sufficient for summarization |
| T-17-03 | Denial of Service | searchArticlesTool limit max | low | mitigate | Zod .max(10) on limit prevents requesting huge result sets from FTS5 |
</threat_model>
