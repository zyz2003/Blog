<task type="auto">
  <name>Task 2: SubscriberService with subscribe, unsubscribe, verification code, and email integration</name>
  <files>server/src/subscriber/subscriber.service.ts</files>
  <action>
Create SubscriberService matching Go backend pkg/service/subscriber/service.go:

1. **Constructor** — Inject: SubscriberRepository, EmailService, SettingsService, MemoryCache, Logger

2. **async subscribe(email: string, code: string)** — Per D-208, full Go Subscribe logic:
   - Verify code from MemoryCache: key `subscribe:code:{email}`. If not found or expired, throw BadRequestException with SUBSCRIBER_CODE_EXPIRED. If code doesn't match, throw BadRequestException with SUBSCRIBER_CODE_INVALID. Delete the key after successful verification (one-time use).
   - Query subscriber by email via repo.findByEmail()
   - If not found: create new subscriber with isActive=true and generated token (call generateToken()). Return success.
   - If found and isActive=true: throw ConflictException with SUBSCRIBER_ALREADY_SUBSCRIBED
   - If found and isActive=false: reactivate by calling repo.updateIsActive(id, true). Per D-208, reactivation instead of new record. Return success.

3. **async unsubscribe(email: string)** — Per Go Unsubscribe:
   - Find subscriber by email via repo.findByEmail()
   - If not found: throw NotFoundException with SUBSCRIBER_NOT_FOUND
   - Set isActive=false via repo.updateIsActive(id, false)
   - Return success

4. **async unsubscribeByToken(token: string)** — Per Go UnsubscribeByToken:
   - Find subscriber by token via repo.findByToken()
   - If not found: throw NotFoundException with SUBSCRIBER_TOKEN_INVALID
   - Set isActive=false via repo.updateIsActive(id, false)
   - Return success

5. **async sendVerificationCode(email: string, captchaParams: any)** — Per D-207 and D-205:
   - CaptchaService verification is handled in the controller (before calling this method)
   - Generate 6-digit code: `crypto.randomBytes(4)` → read as UInt32BE → modulo 1000000 → zero-pad to 6 digits. Matches Go's algorithm exactly.
   - Store in MemoryCache: key `subscribe:code:{email}`, TTL 300000ms (5 minutes) per D-205
   - Call emailService.sendVerificationEmail(email, code) — silently skips if SMTP not configured
   - Return success

6. **async notifyArticlePublished(article: { title: string, url: string })** — Per Go NotifyArticlePublished:
   - Get active subscribers via repo.findActiveSubscribers()
   - For each subscriber, send email with unsubscribe link: `{siteURL}/api/public/unsubscribe/{subscriber.token}`
   - Read siteURL from SettingsService.get('SITE_URL')
   - Add 100ms delay between emails to prevent SMTP rate limiting
   - Wrap each email send in try-catch, log failures but continue
   - If SMTP not configured, silently skip (EmailService handles this)

7. **private generateToken()** — Per Go generateToken:
   - `crypto.randomBytes(32).toString('hex')` — produces 64-char hex string
   - Matches Go's 32-byte random → hex encoding

8. **private generateVerificationCode()** — Per Go SendVerificationCode:
   - `const buf = crypto.randomBytes(4); const code = buf.readUInt32BE(0) % 1000000; return code.toString().padStart(6, '0');`
   - Matches Go's crypto/rand + binary.BigEndian.Uint32 % 1000000 exactly
