    Create ThumbnailService in server/src/thumbnail/thumbnail.service.ts. Inject DRIZZLE and SettingsService. Import crypto from Node.js for HMAC. Import sharp. Import isThumbnailableExtension from server/src/file/utils/file-system.ts. Import decodePublicID, generatePublicID, EntityType from server/src/common/utils/sqids.util.ts.

    **Configuration:**
    - THUMBNAIL_DIR = 'data/uploads/thumbnails'
    - THUMBNAIL_MAX_WIDTH = 400, THUMBNAIL_MAX_HEIGHT = 400 per D-104
    - THUMBNAIL_FORMAT = 'webp' per D-104
    - SIGN_EXPIRY_SECONDS = 900 (15 minutes) per D-105
    - HMAC_SECRET = read from SettingsService with key 'HMAC_SECRET' on first use (lazy init). If not found, generate a random 32-byte hex string and store via SettingsService.set('HMAC_SECRET', value). This ensures the secret is consistent across restarts.

    **generateThumbnail(fileId: number, entitySource: string, fileName: string):**
    1. Check isThumbnailableExtension(fileName) — if not thumbnailable, return null (skip silently)
    2. Ensure THUMBNAIL_DIR exists (mkdir -p)
    3. Use sharp to read entitySource, resize to max 400x400 (fit: 'inside', withoutEnlargement: true), output WebP
    4. Save to data/uploads/thumbnails/{publicID}.webp where publicID = generatePublicID(fileId, EntityType.File)
    5. Return thumbnail file path
    6. On error: log warning but do NOT throw — per D-106, thumbnail failure does not block file upload

    **getThumbnailSign(publicID: string):**
    1. Decode publicID with EntityType.File to get file DB ID
    2. Check if thumbnail file exists on disk at data/uploads/thumbnails/{publicID}.webp
    3. If not exists: synchronously generate thumbnail per D-106 (find entity source from DB, call generateThumbnail)
    4. Generate HMAC-SHA256 signed token per D-105: payload = `${publicID}:${expiresAt}`, signature = HMAC-SHA256(secret, payload). Token = `${publicID}:${expiresAt}:${signature}`
    5. Return { sign: signedToken, expires: expiresAt, obfuscated: true } per RESEARCH Section 5

    **serveThumbnailContent(signedToken: string):**
    1. Parse signedToken: split by ':' -> [publicID, expiresStr, signature]
    2. Recompute expected signature: HMAC-SHA256(secret, `${publicID}:${expiresStr}`)
    3. If signature mismatch, throw 403 with THUMBNAIL_SIGN_INVALID
    4. If Date.now() > parseInt(expiresStr) * 1000, throw 403 with THUMBNAIL_SIGN_EXPIRED
    5. Decode publicID to verify it is EntityType.File
    6. Return { filePath: data/uploads/thumbnails/{publicID}.webp, mimeType: 'image/webp' } for controller to stream

    **regenerateThumbnail(publicID: string):**
    1. Decode publicID with EntityType.File
    2. Find file and entity records from DB
    3. Delete existing thumbnail file from disk if exists
    4. Synchronously regenerate with sharp
    5. Return { status: 'ready' } with HTTP 200 (NOT 202 like Go backend — sync vs async per RESEARCH Section 5)

    **regenerateDirectoryThumbnails(directoryPublicID: string):**
    1. Decode publicID, find directory
    2. Find all descendant file records (type=1)
    3. For each file: delete old thumbnail, regenerate synchronously
    4. Return { message: '缩略图重新生成完成', filesToProcess: count } with HTTP 200

    **createDirectLinks(fileIds: string[], ownerId: number):**
    1. Decode each publicID with EntityType.File to get file DB IDs
    2. Batch lookup files in DB by IDs
    3. For each file:
       - Check if direct link already exists for this fileId (unique constraint on direct_links.fileId per RESEARCH Section 6). If exists, reuse it
       - If not, create new direct_links record: fileId, fileName=file.name, speedLimit=0, downloads=0
    4. For each created/found link:
       - Encode link ID with EntityType.DirectLink=7 per D-107 and RESEARCH Pitfall 5
       - Get site URL from SettingsService (key: 'site_url')
       - Build full URL: `${siteURL}/api/f/${linkPublicID}/${encodeURIComponent(fileName)}`
       - Compute virtual URI by walking ancestor path: `anzhiyu://my/{ancestor1}/{ancestor2}/{fileName}`
    5. Return array of { link, file_url } per RESEARCH Section 6

    **handleDirectDownload(publicID: string, fileName: string):**
    1. Decode publicID with EntityType.DirectLink (NOT EntityType.File) per D-107 and RESEARCH Pitfall 5
    2. Look up direct_links record by DB ID
    3. Increment downloads counter (async, non-blocking per RESEARCH Section 6)
    4. Follow link.fileId to get file record
    5. Follow file.primaryEntityId to get entity record
    6. Get entity.policyId -> look up storage policy
    7. For local storage per D-108:
       - Return { filePath: entity.source, fileName: directLink.fileName or requested fileName, mimeType: entity.mimeType, size: entity.size } for streaming
    - Controller will set Content-Disposition: `attachment; filename*=UTF-8''${encodeURIComponent(fileName)}` and Content-Type from mimeType
